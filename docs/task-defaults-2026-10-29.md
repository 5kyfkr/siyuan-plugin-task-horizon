# 任务默认配置调整

日期：2026-10-29。

## 筛选入口

首次使用时，顶栏下拉菜单直接平铺：全部、未完成、今日、已逾期、未来七天、未安排。不设置“更多预设”，不保留“所有任务”“高重要性”和“已完成”内置规则。列表原有的已完成任务分组继续保留。

| 入口 | 条件 | 排序 |
| --- | --- | --- |
| 全部 | 沿用当前来源及已完成显示设置，不附加规则 | 文档顺序 |
| 未完成 | 排除已完成和已取消 | 重要性降序、截止日期升序 |
| 今日 | 未完成，任务日期区间覆盖今天；打卡按有效计划日期 | 截止日期升序、重要性降序 |
| 已逾期 | 未完成，已经超过截止时间 | 截止日期升序、重要性降序 |
| 未来七天 | 未完成，任务日期落在明天起连续七天内 | 任务日期升序、重要性降序 |
| 未安排 | 未完成，没有有效任务日期 | 重要性降序 |

置顶任务优先，排序同值保留原有文档顺序。日期空值在升序和降序中始终置底。只有日期的截止值在该日结束后才算逾期，带具体时间的截止值按对应时刻判断。任务日期沿用截止日期优先、开始日期兜底、打卡有效计划日期的字段读取逻辑。

新建自定义规则继承当前规则的排序；“全部”下新建规则沿用文档顺序，不自动启用综合打分。

## 状态与命名

新安装默认状态为待办、进行中、已完成、放弃；放弃沿用上版的状态 ID `cancelled`、灰色 `#9E9E9E` 与语法标记 `-`。勾选完成和取消勾选继续绑定已完成、待办。已有状态列表及任务属性保留，受阻、待审核可以通过添加状态配置。

状态设置沿用原有布局，名称、颜色、状态 ID 与语法标记全部直接展示，不设置高级收起逻辑。

手动高、中、低字段统一称为“重要性”，算法分数统一称为“优先级分值”。内部字段键不改动，旧 AI 重要性输入别名继续兼容。

## 迁移与恢复

- `filterRulesDefaultsVersion` 随设置同步到云端和本地；保存过的空列表不自动补回。
- 删除内置 `default_all`、`high_priority`、`default_completed`，将当前选择、视图配置、快捷入口及数量角标中的对应引用回退到全部。
- 已有规则的名称、筛选与排序保留；今日旧条件沿用已有的打卡计划日期兼容迁移。
- 仅首次使用生成五条默认规则；已存在的本地或云端规则列表不自动补入任何新规则，显式保存的空列表同样保留。
- “恢复推荐规则”经用户明确确认后恢复五条推荐规则，保留用户自定义规则及任务数据。
- 现有已完成显示、分组、任务范围、勾选绑定、取消与成功完成的统计语义继续沿用。
