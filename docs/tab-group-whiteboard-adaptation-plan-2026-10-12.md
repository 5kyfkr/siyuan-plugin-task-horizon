# 页签组白板适配方案评估

日期：2026-10-12。状态：已实现并完成行为回归。

建议采用统一范围解析，补齐页签组全部页签的白板、时间轴依赖线和白板顺序。页签组全局画布独立保存，单文档总览继续复用成员文档白板。改动规模中等，主要复杂度在范围和读写一致性。

## 1. 功能边界

| 功能 | 页签组全部页签的行为 |
| --- | --- |
| 全局白板 | 页签组独立保存任务位置、放置状态、连线、便签、手写、分组框、子任务拆离和缩放平移 |
| 单文档总览 | 只展示组内符合当前显示条件的成员文档，复用各文档已有布局和连线 |
| 卡片流 | 使用页签组任务投影，文档排序按页签组保存；已有时间、象限、任务分组继续工作 |
| 时间轴依赖线 | 新增页签组来源，显示、新增、删除和依赖顺延都使用同一来源 |
| 白板顺序 | 新增页签组来源，使用该画布的连线、放置状态和拆离状态计算顺序 |
| 手机、Dock、桌面入口 | 正确显示模式和当前来源；切换模式保留活动页签组 |
| 任务详情白板路径 | 按已有放置记录列出“页签组白板 · 组名”，支持多个组独立路径和跳转；冻结节点只读 |

保留全局白板、单文档总览和卡片流三种显示模式。页签组体现为独立的数据范围。白板模式偏好继续使用现有配置，首期不增加每组独立的模式偏好。

## 2. 来源设置与兼容规则

时间轴依赖线和白板顺序继续分别配置；共享解析逻辑和来源选项定义。

| 来源 | 时间轴配置值 | 顺序配置值 | 含义 |
| --- | --- | --- | --- |
| 各文档白板 | `local` | `document` | 成员文档各自的连线 |
| 文档分组全局白板 | `global` | `global` | 当前文档分组全局画布 |
| 页签组白板 | 新值 `tabGroup` | 新值 `tabGroup` | 活动页签组的独立全局画布 |

- 保留旧值、旧默认值和旧含义；通过薄适配把 `local` 与 `document` 转为内部的同一种文档来源。
- 单文档时间轴继续固定使用本文件连线。白板顺序保留既有行为：即使候选任务来自单文档，显式选择文档分组全局白板时仍考虑跨文档前置任务。
- `tabGroup` 以活动的“页签组全部页签”为依据；没有活动页签组时回退当前文档分组全局白板，单文档时间轴仍按上一条处理。在设置说明中明确该规则。
- 成员文档可能属于多个页签组，直接打开单文档时不推断它属于哪个页签组白板。
- 两套配置可以选择不同来源，各自的读取、写入和计算必须与所选来源一致。

## 3. 实现结构

增加一个白板范围解析函数，例如：

```js
__tmResolveWhiteboardScope({ activeDocId, currentGroupId, source })
// => { kind, docGroupId, tabGroupId, docIds, boardKey }
```

其中 `source` 支持当前画布、各文档、文档分组全局和页签组。当前画布来源用于白板渲染和交互；两个现有设置分别提供明确的来源。成员集合从现有文档／页签组范围函数取得，避免另建成员缓存。

- 渲染、任务池、拖拽坐标、手写、便签、分组框和新建操作共用解析结果，移除相关路径上重复的 `activeDocId === 'all'` 判断。
- 保留现有文档与全局白板读写实现，增加小型连线读写适配，供时间轴与白板顺序复用。存储类型只有文档和聚合画布两种，文档分组与页签组使用不同的画布键。
- 现有全局白板接口接收明确的 `boardKey`；原有默认读取文档分组的含义保持稳定，避免旧 `global` 配置隐式变成页签组来源。
- 时间轴依赖解析保留自身“单文档固定来源”的规则。顺序计算继续使用既有图算法，仅替换取得图数据的入口。
- 时间轴创建、删除和顺延在加入操作队列前捕获来源与画布键，执行时使用已捕获范围；避免排队期间切换页签导致写入另一画布。
- 单文档新建只接收真实文档 ID；聚合画布新建复用现有目标文档解析，页签组虚拟 ID 不进入文档 API。

实现以函数和现有模块为单位；无需引入新的白板类、插件层或消息总线。

## 4. 存储与数据范围

复用现有 `whiteboardGlobalBoardsByGroup` 与 `whiteboardAllTabsDocOrderByGroup` 映射。文档分组沿用原键；页签组键复用 `__tmBuildDocTabCustomGroupActiveId(groupId)`。现有序列化接受字符串键，但范围解析和删除逻辑必须同步识别页签组键。

- 旧画布不自动搬迁或复制，页签组独立画布首次为空；单文档总览仍显示各文档已有布局。此前共享的上层布局没有可靠的页签组归属。
- 当前存储归一化会丢弃只有缩放平移、没有其他内容的非 `all` 画布。若承诺空画布也记住视角，需保留含有效视角的条目。
- 保存、共享状态同步、手写撤销和现有白板整体撤销必须保留页签组键。整体撤销沿用已有行为，并验证操作范围，避免首期重写撤销系统。
- 显式删除页签组或上层文档分组时清理对应画布、卡片流排序和相关运行时缓存。仅因元数据尚未加载或当前筛选为空时不清理。

区分完整成员范围、已加载数据和当前可见任务：

- 画布范围由实际成员关系决定，搜索、规则、完成状态和页签显示控制当前呈现。
- 全局收集文档沿用现有额外来源规则，在解析结果中单独纳入有效任务范围。历史冻结节点继续以只读形式参与画布展示。
- 连线显示只绘制当前可见端点；依赖顺延与顺序计算使用所选来源内的完整有效图，保留被显示筛选隐藏的前置／后续任务。
- 页签组来源的编辑和日期顺延不得越出其有效任务范围，冻结节点不能修改日期。选择文档分组全局来源时，计算范围仍是该文档分组全局图。
- 后台刷新及任务移入移出按对应画布成员范围处理，确认数据完整后才执行已有清理／冻结策略，避免把未加载或暂时隐藏的任务误判为离开分组。

## 5. 改动范围与执行顺序

主要涉及白板运行时、白板渲染与交互、场景和菜单入口、时间轴依赖运行时、白板顺序入口、设置和存储生命周期。保留甘特连线绘制算法和依赖顺延算法。

1. 完成范围解析和带页签组键的存储读写，验证旧值兼容与画布隔离。
2. 接入白板三种模式、工具、新建及桌面／手机／Dock 入口。
3. 扩展两个来源设置，接入时间轴读取、创建、删除、顺延和白板顺序。
4. 完成成员变化、删除、同步和恢复场景的行为回归。

优先在既有行为测试中添加页签组用例；确有独有覆盖时增加一个范围行为测试。避免为每个新函数单独建立源码字符串检查。

## 6. 验收条件

- 同一文档出现在两个页签组时，两个组的全局布局、连线和卡片流排序独立；单文档总览继续复用同一文档白板。
- 三种视图范围均能正确选源；旧 `global` / `local` / `document` 配置结果保持兼容，新增来源回退规则明确。
- 在时间轴新增或删除连线后，选定白板与时间轴一致；依赖顺延和白板顺序使用各自选定来源，顺延可一步撤销。
- 搜索、完成、归档、递归子文档及成员变化不会混入其它组任务，也不会因隐藏或未加载而误删布局。
- 手机切换白板模式保留活动页签组；切换页签期间排队操作仍写入原画布。
- 便签、手写、分组框、拖拽、缩放平移在刷新重开及共享状态同步后恢复正确；覆盖新建空画布视角的保存。
- 现有时间轴依赖、白板顺序、全局收集与冻结、批量保存和页签组行为回归通过。

实现复用现有运行时模块、存储映射和图算法，新增统一范围解析与小型连线读写适配。白板模式、时间轴来源与顺序来源、任务详情路径均已接入。详情路径扫描当前文档分组下已有画布，直接选中明确的页签组路径，不推断单文档的所属组。

新增 `whiteboard-tab-group-scope.test.js` 和 `whiteboard-tab-group-browser.test.js`，覆盖画布隔离、递归成员、空画布视角、来源兼容、手机模式切换、连线读写、排队期间切换页签、顺延范围、成员移出后的冻结节点、详情路径及定位。既有时间轴、顺序、分组删除、项目可见性和菜单测试补齐共用函数的运行环境。完整套件共 377 个测试文件分段验证通过；最终安装包另行检查源码一致性。
