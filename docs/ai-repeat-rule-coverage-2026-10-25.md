# AI 循环规则覆盖检查

检查范围：任务“循环设置”中的所有原生模式，包含自定义循环的按计划打卡。

| 原生设置 | AI 写入方式 | 结果 |
| --- | --- | --- |
| 不循环 | `type: none` | 支持 |
| 到期后重复 | `trigger: due` | 支持 |
| 完成后重复 | `trigger: complete` | 支持 |
| 按计划打卡 | `trigger: checkin`、`anchorDate` | 已补齐 |
| FSRS 间隔重复 | `type: fsrs` | 已补齐原生卡片初始化 |
| 天／工作日／周／月／年及每 N 周期 | `type`、`every` | 支持 |
| 每周多选日期 | `weekdays` | 支持，兼容原生规则的空列表 |
| 每月多日期、月末 | `monthDays`，月末为 `-1` | 支持 |
| 每月第 1–5 个／最后一个星期几 | `monthlyMode: weekday`、`monthWeek` | 支持 |
| 农历月／年 | `calendarMode: lunar` | 支持 |
| 永不结束／按日期／按次数结束 | `until`、`maxOccurrences` | 支持，日期与次数互斥，FSRS 遵循原生规则 |

打卡计划由 `anchorDate` 持有起始日期，任务自身的开始、截止日期保持为空。跟随提醒使用该打卡计划；只配置循环不新增提醒，明确要求提醒或通知时才创建。修改计划保留已有打卡记录。

FSRS 设置复用现有 `50a-fsrs-runtime.js` 的初始化逻辑和已随插件提供的 ts-fsrs 库。打卡记录和 FSRS 评分仍使用任务原有入口，不能用普通任务的永久完成标记代替。

AI 接口现兼容原生循环规则返回的 `version` 字段及空星期列表，因此读取规则后再次写回不会被接口拒绝。

新增隔离回归覆盖 30 种原生规则组合、规则往返、打卡提醒、保留历史、新建任务和重启恢复。其余验证复用原生打卡、FSRS、普通循环和番茄钟提醒测试；未在真实客户端验证模型调用和通知送达。
