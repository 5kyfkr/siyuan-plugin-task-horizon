# 首页打开后插件区域无法交互：排查记录

日期：2026-10-18。检查对象：当前工作区源码，`plugin.json` 标记版本 3.2.4；反馈用户实际安装版本尚未确认。

2026-10-19 更新：已定位并修复表格宽度监听器误用于首页造成的持续重建，用户确认问题已解决。本轮自动诊断日志、输入与异常采集监听、任务规模扫描、耗时统计及快照生成逻辑现已移除；宽度监听保护、交互恢复和主题值比较修复保留。下文保留排查过程中的历史记录，所列临时日志不再由当前版本生成。

## 当前判断

反馈现象为：首页已经显示，但插件区域的按钮和滚动都失效；思源顶部工具栏仍可点击；启用了第三方主题和番茄钟。

优先排查插件区域的鼠标命中和交互状态。顶部仍能响应使“整个渲染主线程持续死循环”的优先级降低，但不能完全排除间歇性长任务。启用了主题和番茄钟只是环境条件，目前没有证据确认某一个是根因。

本地正常流程未复现故障。下文可疑路径按修复前源码记录，不是对用户现场的根因确认；交互恢复路径已按用户要求修复，验证结果见文末。

## 优先排查的路径

### 1. 视图切换后插件外壳遗留 `pointer-events: none`

- `src/task-horizon/main/40-render-runtime.js:60`：只有视图切换动画或保留外壳标记启用时，才进入 `useSoftSwap`。
- 同文件第 313、475 行：旧外壳及新外壳会临时设置 `pointerEvents = 'none'`。
- 同文件第 1986–1987 行：插入新外壳后调用侧栏挂载；交互恢复发生在后面的首页分支（第 2243–2251 行），通过两次 `requestAnimationFrame` 执行。
- 恢复前若渲染异常退出，没有统一的交互恢复兜底。`tmOpenHomepage` 还会吞掉最终 `render()` 的异常，见 `src/task-horizon/main/render/47-render-side-panels-and-view-switching.js:415`。

这可以形成“界面已显示，但整个插件无法点击和滚动”的状态。需要现场确认外壳或祖先的计算样式是否为 `pointer-events: none`，并找到最早的异常。普通进入首页不一定走此分支，不能仅凭这段代码认定根因。

### 2. 页签/侧栏中显示的是静态快照，恢复实时界面失败

- `src/task-horizon/main/20-api-and-runtime-services.js:17392`：跨宿主保留界面时会克隆外壳。
- 第 17420 行添加 `data-task-horizon-dock-snapshot="1"`；后续移除子节点 ID、内联事件属性，克隆本身也不保留通过 `addEventListener` 注册的监听器。
- `task-horizon.css:3206`：快照所有后代统一应用 `pointer-events: none !important`，所以里面的按钮和滚动区不是正常工作界面。
- `src/task-horizon/main/20-api-and-runtime-services.js:17363`：快照根节点本应收到一次点击，清除快照并重新挂载实时界面。

如果宿主切换后只留下快照，且点击恢复链路异常、被遮挡或根节点本身不可命中，就会表现得像卡死。需要确认现场快照标记、实时外壳所在宿主及点击命中元素。截图本身不足以证明显示的是快照。

### 3. 主题或其他界面层覆盖插件区域

透明遮罩、错误的尺寸或层级、祖先的 `inert`、桌面窗口拖动区域样式，都可能造成局部界面有画面却无法交互。应使用 `elementsFromPoint()` 获取按钮坐标上实际收到鼠标的元素，再追踪该元素来源。

未在首页初始化路径发现主动覆盖整个插件的遮罩或吞掉全部点击的全局监听器。首页的专注统计异步请求有超时/错误处理，单纯请求拒绝或挂起通常只影响统计模块；这不能排除第三方代码执行同步长任务，也不代表已经验证真实番茄钟插件的兼容性。

## 现场确认方法

1. 卡住时保留页面状态，在思源开发者工具 Console 中执行 [只读诊断脚本](../scripts/diagnose-homepage-interaction.js) 的全部内容，保留输出，同时记录打开首页时最早出现的 Console 异常。
2. 查看 `visibleShells` 和 `samples`：
   - 外壳或祖先 `pointerEvents: "none"`：优先追踪切换动画恢复路径，或计算样式的来源。
   - `snapshotKind: "tab"/"dock"` 或存在 `snapshotAncestor`：确认快照恢复和宿主挂载流程。
   - 按钮 `hitExpected: false`，且 `hitStack[0]` 是其他层：追踪该遮挡元素及样式来源。
   - `inertAncestor` 非空或 `appRegion: "drag"`：检查相应祖先状态或主题样式。
   - 高 `mutationRecords` 或明显延长的 `sampleElapsedMs` 只是线索，需要 Performance 记录判断循环或长任务，不能单独定性。
3. 再分别做环境对照：先只切换默认主题并重开首页；恢复原主题后，只禁用番茄钟并重开首页。不要同时关闭两者，否则不能区分触发条件。

诊断脚本只读取 DOM、样式和命中结果，临时观察约 500ms 后输出；不修改任务、设置或界面，不发送网络请求，不采集任务正文。若现场版本没有运行时外壳接口，`isLive` 字段不能单独用于判断。

## 取得现场证据后的修复方向

- 若确认外壳禁用遗留：对本次渲染的局部外壳恢复交互，增加异常路径清理，并防止旧动画回调操作后续新外壳。
- 若确认快照残留：修复宿主激活/恢复链路，保证恢复失败后仍可重试，检查是否继承了不可交互状态。
- 若确认第三方层遮挡：按实际覆盖元素修正选择器、范围或层级，避免无差别提高插件层级或强制启用全部鼠标事件。

## 已实施：切换交互恢复修复

按用户要求先修复第一条路径，未将其宣称为用户现场的已确认根因。

- 每次全量渲染分别记录本次切换的旧容器、旧内联样式和新容器，在 `render()` 的 `finally` 中统一收尾。

## 新增：首页交互与窗口切换控制台日志

运行时现在会在打开首页时，以及首页打开期间窗口失焦、重新聚焦或页面可见性切换时，向 Console 输出 `[task-horizon][homepage-interaction-diagnostic]`。内容以单行 JSON 文本输出，避免 DevTools 折叠对象。每个触发点包含即时快照和约 700ms 后的稳定快照；后续事件会刷新稳定快照。

现场复测时打开开发者工具 Console，过滤 `homepage-interaction-diagnostic`，在首页保持打开的状态下切到其他程序再切回思源。请保留切换前、`window-blur`、`window-focus`、`window-visibility-*` 以及各自 `settled-700ms` 的输出；弹窗样式变化应能从 host mode、外壳 className/position/rect 和命中栈的差异看出来。开发安装重载插件即可加载源码日志；打包安装需使用包含本次源码的新版插件。

## 2026-10-19 用户现场日志结论

用户提供的 `新建文本文档 (2).txt` 包含 9628 行，其中 9586 行为首页事件日志。首页在约 70 秒内产生了 745 次 `mount-start`，每秒约 4 到 13 次；对应的 `mount-complete` 均显示首页已绑定点击处理器。首页任务收集通常为 12 个任务、44 个加载任务、3 个文档，`recurringInstanceCount`、`recurringSourceCount`、`checkinSourceCount` 和两类历史条目均为 0，任务扫描和项目构建大多为 0 到 2 毫秒。因此这份日志不支持循环任务数量过多或打卡历史拖慢首页。
