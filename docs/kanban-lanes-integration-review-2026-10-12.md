# 看板两种外观接入说明

更新日期：2026-10-12。

## 当前实现

- 两种外观共用任务渲染、卡片 DOM、拖拽、分组、折叠、页签和局部刷新。
- 默认使用“竖向分区”，另一个选项命名为“卡片样式”。已明确保存的外观选择保留。
- 设置位置：设置 → 视图 → 时间轴、看板与白板 → 看板外观。使用与“全部页签时间轴依赖线”相同的分段切换控件，选项为“竖向分区 / 卡片样式”。
- 分区颜色浓度默认 15%，可在 6%–30% 之间调整，设置仅在竖向分区模式显示；预览直接更新背景，不重建任务卡片或改变滚动位置。已有用户保存的自定义浓度保留。
- 分区没有列边框和顶部背景圆角，底色随内容向下变淡，相邻列之间直接插值颜色，不先淡到白色，也不叠加半透明色块。
- 卡片左右留白统一为 10px，普通、紧凑和侧栏模式均使用这个值。
- 标题头最低 44px，任务区按列独立滚动，列标题保持可见。
- 折叠列显示为无边框竖条，高度随标题、数量、进度和展开按钮的实际内容收缩，底色随竖条高度淡出；竖条结束以下的接缝仍与相邻列柔和衔接，移动与侧栏页签仅定位列，不自动展开。
- 4px 满宽圆角进度条只显示在标题看板（含按文档分列）。状态和时间看板不计算项目进度。

## 项目进度复用

看板复用首页项目进度的统计函数、文档缓存和批量读取。没有另建任务统计服务，也不加载首页界面模块。

公共函数位于 `20-api-and-runtime-services.js`：

- `__tmCreateProjectTaskStats()` 创建统计结果。
- `__tmAddProjectTaskToStats()` 沿用首页口径，包含子任务，完成或取消任务计入已结束项。
- `__tmGetProjectProgressPercent()` 优先使用首页已缓存的完整文档进度，缓存缺失时以已加载的项目任务统计为临时值。
- 文档列复用 `__tmLoadDocProgressBatch()` 的缓存、批量 SQL 请求和失效处理，适用于本地任务尚未全部加载的文档。
- 标题列以对应标题范围的完整已加载任务聚合计算。看板配置的标题级别沿用现有标题分组解析。

进度表示整个项目/文档/标题的完成度，与首页保持一致；搜索、规则筛选、完成显示开关和分批挂载不改变整个项目的完成度。列头的任务数量仍使用现有可见根卡片数量，两者含义不同，进度辅助文本标明“项目进度”。

统计只装饰现有列，不参与生成列。归档文档、空收集箱、完成任务独立列等是否显示，仍遵循两种外观共用的原有规则。

## 维护边界

- 设置字段：`kanbanAppearance: 'lanes' | 'classic'`。缺失或非法值默认 `lanes`；明确的 `classic` 选择保留。
- 颜色浓度使用 `kanbanLaneColorStrength`，沿用本地保存、同步读取和导入合法值归一，切换为卡片样式时保留数值供再次启用分区使用。
- 本地存储、同步读取、设置合法值归一和设置界面均沿用已有路径。
- 看板根节点通过 `data-kanban-appearance` 选择外观，新增 CSS 限定在实际看板中，避免影响白板。
- 任务卡片 DOM 和 `.tm-kanban-col-body` 的直接子级约定保持不变。
- 背景位于公共绝对定位层，列与卡片保留原有性能隔离。背景不拦截指针事件，也不裁剪看板横向滚动。
- 使用一个公共 Canvas 背景层，先绘制各列垂直底色，再在接缝直接插值两侧颜色；普通交界过渡宽 56px，涉及折叠列时为 24px。两侧颜色已与宿主背景合成，不会再重复叠加浓度或出现白色中心线。
- 最后一列右侧存在空白空间时，以更短的 28px 过渡直接插值到页面底色，折叠末列使用 16px；背景层不额外增加横向滚动宽度。
- 背景只随布局、内容和浓度变化重绘，画布宽度最多 8192px，不按设备像素倍率扩大；较多列时按横向比例绘制，限制内存占用。卡片样式不创建这个画布。
- 背景尺寸、观察器和进度读取集中在 `40-render-runtime.js`，通过动画帧合并更新。
- 状态、时间模式不订阅进度更新；卡片样式不创建新的背景或进度观察器。
- 关闭、切换视图、切回卡片样式时清理观察器、任务订阅和待执行帧。
- 在页签与 Dock 之间切换宿主时先停用背景更新，保留已绘制的画布供冻结快照复制；快照显式复制 Canvas 像素，冻结页面不再依赖实时背景会话。
- 外观切换使用现有视图内刷新，保留列内滚动与折叠状态，并根据新间距重新定位当前列。
- 继续通过现有 manifest 构建 `task.js`，不直接修改生成文件。
