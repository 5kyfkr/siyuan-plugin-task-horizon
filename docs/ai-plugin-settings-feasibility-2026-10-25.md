# AI 读取、推荐及修改插件设置：可行性评估

日期：2026-10-25。对象：Task Horizon／任务管理器 3.3.0，当前工作区源码；HEAD 为 `5f45f27`，包含评估前已有的未提交修改。

评估后按用户确定的最小范围实现：仅新增思源原生智能体的只读前端能力 `query_plugin_settings`。首批 12 个常用设置与设置页面共用名称、说明，返回实际页面路径、当前值及作用范围；免费用户可用。没有新增定位动作、自动修改、聊天界面或模型配置，现有付费工作台和任务 MCP 权益保持原样。支持省略 `query` 查看目录，或传入“手机字太小”“任务完成后消失”等关键词查询。

下文保留评估与后续建议，其中尚未落地的工具和阶段不属于当前实现。

当前实现已通过 `scripts/agent-settings-query.test.js`（免费状态、首次加载、当前分组、只读与凭据隔离）、前端能力兼容测试、内核权益测试及设置页面浏览器回归；桌面／移动布局在 320–1440 px 宽度下通过。尚未在真实思源客户端执行模型对话验证。

## 结论

三类能力都能实现，适合分阶段交付。

| 能力 | 可行性 | 实施复杂度 | 首版建议 |
| --- | --- | --- | --- |
| AI 查找设置项，解释用途与所在位置 | 高 | 低至中 | 优先实现，复用设置搜索与定位 |
| AI 读取当前值，按用户描述推荐具体设置 | 高 | 中 | 同首版实现，返回建议值、理由及作用范围 |
| AI 修改一部分常用设置并即时生效 | 高 | 中 | 增量开放明确登记的设置 |
| AI 无差别修改所有设置、任意配置对象 | 需逐项适配 | 高 | 不作为首版承诺 |

复评后的首版建议：仅做设置查询、必要的当前值读取、推荐和定位，查询与读取合并为一个接口；自动修改延后。下文完整修改方案保留作为后续参考，不作为首版工作范围。

## 简洁性与免费范围复评

### 是否足够简洁

原方案适合作为完整能力设计，作为验证需求的首版偏重：四个工具、设置写入登记、持久化核验、并发和撤销并非设置问答的必要前提。保存失败的核验问题应在真正开放修改时解决，不必成为只读设置助手的前置改造。

建议首版只增加两个前端能力，名称为建议：

| 接口 | 首版职责 |
| --- | --- |
| `query_plugin_settings` | 查询候选设置，返回名称、说明、真实路径、允许读取的当前值和适用范围 |
| `open_plugin_setting` | 打开并高亮已有设置控件，用户使用原控件修改 |

先覆盖约 10–20 个高频设置，利用已有搜索元数据及少量明确登记的值读取器。保留未打开设置时索引就绪的处理。前端返回少量候选项，模型负责理解用户描述和解释建议；当前关键词搜索不等同于语义推荐，需要模型调用验证。首版不增加通用设置写入器、独立模型配置、向量库或第二套会话系统。

### 有没有必要做

值得作为小范围的帮助功能尝试，优先级应低于影响日常使用的错误修复、性能和主要任务流程。其价值假设是帮助用户找到已有能力、减少重复解释设置的支持工作；当前没有查询日志或支持工单统计，不能断言能提高留存或付费转化。

真正适合验证的需求是“我描述想要的效果，你告诉我改哪里”，例如任务完成后消失、手机字号、字段布局。自动修改的增量价值要在推荐与定位被实际使用后再判断。

若必须为此新建一个免费 AI 工作台、模型接入和会话管理，首版投入不合适。若能借用已有原生智能体，只补小型查询入口和定位能力，则具备尝试价值。

### 免费用户能否只开放这一项 AI 能力

可以。这里理解为“免费用户获得设置助手，完整任务 AI 仍属付费”；付费用户也包含设置助手，不建议反向排除付费用户。

当前代码把两个产品权益分开：

- `47-render-side-panels-and-view-switching.js` 中的 AI 工作台入口要求全功能权益。
- `81-ai-bridge-runtime.js` 中的任务 MCP 可用性依赖全功能权益；设置页面也明确免费版不启用任务 MCP。
- 设置页面说明思源自身的智能体独立使用，模型、密钥及通用会话由思源管理。
- `index.js` 已有前端能力注册通道，可新增公开的设置查询与定位能力，并保留任务领域工具原有权益判断。

成本最低的交付方式是在思源原生智能体提供设置查询与定位，不开放插件付费工作台，也不新建免费通用聊天界面。实际原生入口调用、插件运行时加载及移动端表现仍需客户端验证。

| 能力 | 免费用户 | 付费用户 |
| --- | --- | --- |
| 设置解释、推荐、读取允许公开的设置值、跳转定位 | 开放 | 开放 |
| 插件 AI 工作台与任务领域工具 | 保持现有权益范围 | 保持现有权益范围 |
| AI 自动修改插件设置 | 首版不做 | 首版不做 |

“插件功能免费”与“模型调用免费”需要分开说明。沿用用户已配置的思源 AI 时，模型调用仍受其服务方案和计费约束；没有配置模型的用户继续使用普通设置搜索。若目标人群主要是未配置 AI 的新用户，应优先改善搜索别名、说明和导航，AI 的直接收益会更小。

后续可依据用户自愿反馈及现有支持问题判断效果，例如能否找到正确项、是否仍需人工解释。不为验证一个小功能先建设复杂埋点系统。

## 后续完整实现参考（不计入首版）

### 1. 设置目录

先复用搜索元数据，再为首批可读、可修改设置增加小型登记表。每项至少包含：

- 稳定的设置 ID，以及当前名称、说明、搜索别名与页面定位目标。
- 值类型、有效选项或数值范围。
- 当前有效值、默认值与来源；没有显式配置时说明继承关系。
- 作用范围，例如桌面端、移动端、Dock、当前文档分组或全局。
- 存储与同步范围，单独说明，避免把“移动端专用值”等同于“只在本机保存”。
- 是否可修改、依赖条件、允许的修改入口及需要刷新的模块。

搜索命中的标题、说明和路径可以复用；搜索索引目前没有提供完整的设置键、类型与 setter 映射，而且部分索引在设置渲染后异步生成。首次使用必须等待索引就绪，或为首批设置提供可独立加载的目录。

当前部分搜索 key 随标题生成，不宜直接作为长期稳定的写入 ID。设置名称或分类调整后，登记表需要维持映射。

### 2. 完整工具集合

以下名称为新工具建议，不是现有接口：

| 工具 | 职责 |
| --- | --- |
| `search_plugin_settings` | 从用户需求检索候选项，返回少量匹配项及真实页面路径 |
| `read_plugin_settings` | 按设置 ID 返回允许读取的有效值、默认值、来源与作用范围 |
| `open_plugin_setting` | 打开并高亮指定设置，复用现有定位函数 |
| `apply_plugin_settings` | 对明确登记的设置执行类型校验、范围核验、保存与结果核验 |

推荐无需单独增加模型工具：模型先检索和读取，再结合用户描述解释候选项、建议值及影响即可。只请求推荐时不执行写入；明确要求修改时，沿用现有批准设置和适用的功能权益检查。

普通交互优先接入 `addAgentCapability`，因为有效设置、当前分组和即时刷新入口都在前端。读操作声明 `localRead`，修改声明 `localWrite`；打开设置页可沿用现有打开任务管理器能力的效果声明方式。

如需内核独立读取，再增加对应 MCP 能力。`kernel.js` 当前读取的是已保存的 `task-settings.json`；它不能代替前端加载、默认值归一化和运行时作用范围解析。现有定时对话禁止前端调用及数据修改，首版不承诺定时自动修改设置。

### 3. 修改入口

为每个开放设置登记明确的修改适配器，复用现有处理函数及 `SettingsStore` 保存流程。适配器自身执行类型、枚举和边界校验；一些现有函数依赖 HTML 控件的约束，不能仅调用函数就认为输入已被完整验证。

需要适配的已有行为举例：

- `updateEnableQuickbar` 保存后还会启停悬浮条、刷新行内字段。
- `updateChecklistCompactMode` 保存后会刷新清单布局。
- `tmToggleShowCompletedTasks` 使用当前文档分组，还会重新投影任务并刷新日历任务列表。
- 桌面端、移动端及 Dock 的部分字段设置有关联更新，不能假设三个作用范围完全独立。

现有 `aiBridge.saveAiSettings(patch)` 是内部配置入口，允许更新已有存储键，缺少通用设置所需的逐项语义与刷新适配，不宜直接暴露给模型作为任意键写入器。

### 4. 写入结果与并发

`SettingsStore.save()` 会合并延迟写入；`flushSave()` 会同步本地缓存并保存文件，但部分异常被捕获，完成时仍可能 resolve。因此，`await save()` 或内存值变更都不足以证明已持久化成功。

写入能力需要补足：

- 在请求中固定目标分组／设备范围及预期旧值，拒绝被手动修改过的目标。
- 在共享修改队列内核验并应用；涉及共享文件时，还需沿用字段合并机制，不能将前端旧值比较描述为跨客户端原子锁。
- 等待现有保存流程完成，并获得明确保存结果；如暂不改保存接口，则重读持久化结果核验本次字段。
- 区分“当前界面已生效”“已保存”“其他客户端已同步”，不能把本地文件落盘描述为所有设备已生效。
- 返回实际旧值、新值、作用范围及失败情况。首版可限制单项修改，减少批量部分成功的问题。
- 撤销只还原本次涉及且仍保持本次值的字段，避免覆盖之后的手动修改。

API Key、WebDAV 密码等凭据不进入模型上下文。相关选项可返回“已配置／未配置”并支持定位手动编辑。授权状态、AI 能力批准策略及内部版本／缓存字段不纳入首批可写设置。

## 用户描述与具体设置示例

以下值是建议示例，不是用户当前配置。

| 用户描述 | 应推荐的实际设置 | 解释 |
| --- | --- | --- |
| 手机里的字太小 | 外观 → 字号与密度 → 移动端字体，例如 16 px | 单独调整移动端字号，控件范围为 10–30 px |
| 字段不要都挤在任务右边 | 视图 → 表格 / 清单 → 清单紧凑模式：关闭 | 字段改为显示在任务名称下方 |
| 完成任务后不要消失 | 任务 → 完成与归档 → 显示已完成任务：开启 | 按当前文档分组记忆；还需读取相关筛选和今天完成限制，不能保证只改这一项就改变所有视图 |
| 不想要完成动画和趣味提示 | 任务 → 完成与归档 → 完成反馈：关闭 | 保留普通完成提示 |

理想输出应包含“具体设置、当前值、建议值、理由、适用范围、前往设置”；有明确修改意图时，再按可用工具执行并返回核验结果。模型只能引用目录中存在的设置；无法对应的需求应说明限制。

## 交付范围与验证

按复评后的范围，第一阶段只实现合并查询、少量允许读取的有效值、自然语言推荐与设置定位，优先覆盖高频显示和任务行为选项。是否进入受控修改阶段取决于实际需求，后续范围再单独确定。文档来源、状态列表、自定义字段、复杂筛选排序和外部订阅不计入首版修改能力。

新功能验收需覆盖：首次未打开设置时可查询；读取不会修改配置；推荐名称与路径确实存在；桌面／移动／分组范围正确；非法值被拒绝；保存失败不报成功；修改后视图更新、重载仍保留；并发手动修改与撤销不覆盖他人变化；凭据不进入模型上下文。模型实际工具选择还需在真实客户端验证。
