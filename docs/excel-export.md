# Excel 附件导出

表格视图的“导出 Excel”继续使用 SheetJS。没有可复制附件时输出 `.xlsx`；有可复制附件时下载 ZIP，内含 Excel 和 `附件/` 目录，解压后再打开 Excel。整体移动或分享时保留目录结构。

- 每个任务仅保留一行。主表按附件数量增加“附件、附件 2、附件 3……”列，每个文件名单独点击即可打开，不跳转到明细表；无附件的单元格留空。
- 文件复制到 `附件/原资源路径`，保留原文件名，不添加流水号。同一附件被多个任务引用时仅复制一次；目标路径重名时仅给冲突文件加 `(2)` 等后缀。过长文件名、Windows 保留名称及影响 Excel 链接解析的字符会做必要调整。图片按原始文件复制。
- 本地相对链接直接使用中文路径，不把中文编码成 `%E9…`。链接目标与 ZIP 内实际路径完全一致，避免 Excel 将编码内容当作文件名导致无法打开。
- 思源 `assets/` 文件通过现有资源地址读取。桌面环境可读取的本地普通文件也一起复制。本地目录、网络链接和思源文档／块引用保留原链接，不递归导出其内容。
- 读取失败会在对应附件单元格标注，并在完成提示中报告数量；其他任务和附件照常导出。附件属性读取失败则停止导出，避免将未知附件状态当作无附件。
- 导出仅补齐缺失的附件属性，使用独立任务副本，不写任务、设置或源附件。
- JSZip 按需加载，只负责 ZIP 打包；SheetJS 负责工作表和超链接。没有图片嵌入、缩略图或 OLE 流程。

回归检查：`node scripts/settings-excel-attachments-behavior.test.js`。已在本机 Excel 16.0 中验证：解压到另一目录后，从任务主表直接打开中文文件名、含空格文件名及调整特殊字符后的文件，并核对目标内容。WPS 原生打开效果尚未验证。
