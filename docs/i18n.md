# Translation maintenance

Task Horizon ships one plugin with English and Simplified Chinese. Maintain the
flat language files `i18n/en.json` and `i18n/zh-CN.json` directly; there is no
translation build pass, generated English source tree, or second plugin identity.

## Runtime

SiYuan supplies its selected dictionary as `Plugin.i18n`. Before loading any task,
calendar, homepage, quickbar, or AI script, `index.js` reads `uiLanguage` from
`task-settings.json`, loads an overridden dictionary if necessary, and creates the
translator in `__taskHorizonHostBridge.i18n`. `system` follows SiYuan; the other
values are `en` and `zh-CN`. The preference belongs to synchronized plugin settings.

Scripts use a local `__tmT` reference to the host translator. Kernel code uses
the same language files through SiYuan's dictionary injection and the synchronized
preference. Its existing settings reader refreshes the selected dictionary;
successive requests reuse cached dictionaries. Never depend on DOM or browser
Intl APIs in shared recurrence functions or kernel code.

Changing the preference persists settings immediately. The user can reload the
interface after pending settings saves complete. Locale-dependent static arrays
are initialized during startup, so there is no partial DOM translation pass.

## Adding or changing text

1. Use a stable semantic key, such as `settings.uiLanguage` or `task.deleteConfirm`.
2. Add the complete message in both files. Edit wording without renaming its key.
3. Use named parameters: `__tmT('task.deleteConfirm', { title })`. Do not place JS
   expressions in JSON, use `eval`, or build sentences by concatenating fragments.
4. Keep markup in JS. Escape translated text and user parameters for their actual
   HTML context with the existing escape helpers, just like other rendered text.
   Use `textContent` for plain text.
5. Count-sensitive messages may use `.one` and `.other` variants. Call the base
   key with `{ count }`; keep the same parameter names across languages.
6. Keep task IDs, enum values, custom names, parser vocabulary, and storage keys
   independent from translated labels. `builtinName` translates only untouched
   built-in records with known IDs and compatibility names.

Avoid dynamic translation keys where a static mapping is sufficient. Weekday and
built-in-name families are the existing exceptions. Date formatting belongs in
the shared frontend formatter; machine-readable dates and time zones keep their
existing semantics. Natural-language date parsing is a separate feature.

Run `node scripts/check-i18n.js`. The release verifier runs this automatically;
the package verifier also compares shipped dictionaries and all README paths with
the current source. Existing source-slice and browser tests use the real translator
through host fixtures. Add a language behavior test when changing language selection,
placeholder handling, defaults, or the persistence flow.

Some older source contracts match Chinese literals and nearby code. Their
`i18n-source-fixture` materializes translation calls as Chinese literals for those
structural assertions only. It does not run translation values as code. Runtime
and browser tests continue to exercise production scripts and the real translator.
Prefer behavior assertions for new tests.

## Documentation and releases

- `README.md` is the English installation and usage guide.
- `README.zh-CN.md` retains the complete previous Chinese README, including history,
  sponsors, acknowledgements, and donation information.
- Both READMEs link to each other. `plugin.json` selects them for the marketplace.
- Update both guides together when installation, workflows, settings paths,
  activation, or data behavior changes. Internal fixes do not require a README edit.
- Write new version notes once in `CHANGELOG.md`, with Chinese and English text
  under the same version heading. Do not append new history to both guides.
- README links to files excluded from `package.zip`, such as `docs/` and
  `CHANGELOG.md`, must use absolute repository URLs.
- Structural checks cannot establish translation quality or documentation accuracy;
  review the wording and representative layouts in both languages.
