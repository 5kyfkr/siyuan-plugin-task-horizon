## 0. 结论摘要

1. **选择器只是表层。** 当前时长值在 4 个运行时里有 4 套解析（主界面、kernel、首页、日历），同一个 `2.5` 可能是 2.5 小时、2.5 分钟或 15 分钟。新控件写数字之前，必须先把这套语义统一，否则会稳定地制造新 bug。
2. **按已确认的“只写数字、当前单位”方案，不需要数据迁移。** 小时模式写 `2.5`，分钟模式写 `150`；显示时再换算成 `2h30m`。
3. **完整方案约 10–16 人日。** 不建议一次做完。建议第一版只做 P0（统一解析）+ P1（A 基础版选择器，3 处），约 5–7 人日；其余分两批。
4. **默认显示格式建议保持“跟单位”**（`1.5h` / `90min`），把 `2h30m` 作为可选项。这样可以避免一次性改掉所有列表/导出/测试的文案。
5. 第一版评估里“新数据写显式单位”的存储建议**作废**，按本次决定改为只写数字。

### 2.4 已确认的现存问题

- `showDurationPrompt` 用 `__tmNormalizeDurationPresetValue` 只取第一个数字：输入 `2h30m` 会变成 `2`，批量/右键修改会直接丢精度。
- 预设编辑器只接受数字，且不显示当前单位；在小时模式下把 `30` 当预设，实际是 30 小时。
- 切换 `durationFormat` 没有任何迁移或提示；`30` 会从 30 小时变成 30 分钟。
- 日历解析器把 `2.5` 夹到 15 分钟，且 `2h30m` 只读小时部分。
- 设置里的「时长显示格式」同时承担“单位”和“显示样式”两个职责，无法安全地只改显示。

## 3. 目标模型

### 3.1 存储

继续存**数字字符串**，单位由 `durationFormat` 决定：

| 模式 | 2h30m 存储 | 45m 存储 | 空 |
|---|---|---|---|
| 小时 | `2.5` | `0.75` | `''` |
| 分钟 | `150` | `45` | `''` |

规则：

- 小时模式最多 2 位小数；读取时 `Math.round(n * 60)` 回到分钟。已验证 0–99 小时的所有分钟值可无损往返。
- 分钟模式写整数。
- 值未变化时不重写（避免 `0.34 → 20m → 0.33` 的二次舍入）。
- 不迁移历史值；旧的 `90分钟`、`1.5`、`2h30m` 继续可读。

### 3.2 显示

新增独立设置（名称暂定）：

- `durationFormat`：保持现有键，语义收敛为**单位**（`hours` / `minutes`）。
- `durationDisplayFormat`：**显示格式**，建议值：
  - `unit`（默认）：小时模式 `1.5h`，分钟模式 `90min`
  - `compact`：`2h30m` / `45m`
  - `clock`：`2:30`
  - `chinese`：`2 小时 30 分钟`

显示格式只影响渲染，不改变存储和解释。默认 `unit` 以保持现有外观和测试稳定。

### 3.3 输入控件

- 小时 + 分钟两个数字框，单位标签，行内预览 `= 2h30m`。
- 内部仍维护一个隐藏的数字值，兼容现有提交路径。
- 预设：`data-value` 保持原数字，标签用显示格式渲染；选中写原数字。
- 宽度：228 → 252px（焦点弹层）；悬浮条沿用 280px。
- 键盘：Tab 切换时/分，Enter 保存，Esc 关闭，上下键步进。
- 移动端：`inputmode="numeric"`，44px 触控高度。
- 校验：小时 0–999，分钟 0–59，合计 > 0 才写入；0/0 视为空。

### 3.4 运行时共享

当前构建把 `src/task-horizon` 打包成 `task.js`，而 `quickbar.js`、`homepage.js`、`calendar-view.js`、`kernel.js` 是独立文件。因此：

- 主实现放在主包，暴露 `globalThis.__tmDuration`。
- quickbar/首页/日历优先调用该全局对象，缺失时用同算法 fallback。
- kernel 保留一份镜像实现，从 `task-settings.json` 读取 `durationFormat`。
- 新建 `scripts/fixtures/duration-cases.json`，四个运行时共用同一组输入/期望值，用契约测试保证不漂移。

## 4. 分期方案

### P0 · 统一解析（前置，必须）

- 新增 `src/task-horizon/main/06a-duration-format.js`（纯函数，不依赖 SettingsStore）：
  - `parse(value, unit)` → 分钟数
  - `format(minutes, displayFormat, unit)` → 字符串
  - `split(minutes)` / `join(h, m, unit)` → 数字字符串
  - `presetLabel(value, unit, displayFormat)`
- 主界面解析器改为调用该模块；补中文单位、`d`、复合值、空值规则。
- kernel 的 `parseDurationMinutes` 读取 `settings.durationFormat`，修正 `aggregate_time_usage`。这是行为修正：小时模式用户的 AI 汇总会从 `2.5m` 变成 `150m`，需要在发布说明里注明。
- 首页解析器对齐（它已支持中文和天，主要改裸数字/复合值的边界）。
- 日历解析器改为单位感知；预估时长不再套用 15 分钟下限，空值不再默认 60 分钟；15 分钟下限与 60 分钟占位只保留在“创建日程事件”这一步，和预估解析分开。
- `showDurationPrompt` 改为“解析为分钟 → 按单位写数字”，不再截断第一个数字。
- **单位切换防护**：切换「时长单位」必须二次确认，并明确提示“历史数字和预设会按新单位重新解释，不做换算”；不能保持现在的静默切换。
- 测试：解析矩阵 + 四运行时一致性 + 0–99 小时往返。

### P1 · A 基础版选择器（3 处）

- 新增 `__tmBuildDurationPicker`（主包），quickbar 通过全局对象复用。
- 替换详情弹层、内联编辑器、悬浮条三处的 `<input type="text">`。悬浮条是独立 bundle，建议拆成 P1b 单独验证；详情/内联可先上。
- 预设标签格式化，`data-value` 保持原数字；预设编辑器至少显示当前单位和格式化预览，避免“30 小时预设”的误配。
- 保持 tabs、标题、字段标签、只读行、按钮、静默二选一。
- 宽度 252px；补 CSS 和移动端。
- 注意：P1 只改控件，列表/chip 仍按 `1.5h` 显示；要全站 `2h30m` 需要 P3。
- 测试：输入/预设/键盘/移动端；预设写原数字；未改动不重写。

### P2 · 其余输入入口

- 表格「时长」单元格、批量修改、右键设置、悬浮条普通时长。
- 统一用同一个 picker；批量/右键弹窗接受 `2h30m` 并写数字。
- 测试：批量修改复合值、单元格编辑、右键菜单。

### P3 · 显示格式

- 新增 `durationDisplayFormat` 设置和设置页控件。
- 把 7 套格式化收敛为 `format(minutes, displayFormat, unit)`。
- 覆盖：列表/表格、清单紧凑字段、看板/白板 chip、悬浮条、详情 chip、分组合计、首页、日历任务卡、导出、AI/摘要、设置预览。
- “实际耗时”：`tomatoSpentAttrMode` 只决定读取哪个属性；显示统一走 `format`。
- 默认 `unit`，避免大面积改文案；用户可切到 `compact`。
- 测试：格式矩阵 + 各视图快照 + 现有契约测试更新。

### P4 · 设置、预设与二选一治理

- 设置页拆成「时长单位」+「显示格式」；单位切换只做二次确认和提示，不做数据换算。
- 预设编辑器显示当前单位和格式化预览；可输入 `30m` / `1h30m` 并换算成当前单位的数字存储。
- 预设值本身也是当前单位的数字；切单位后按新单位重新解释，提示中要说明。
- 数据层强制“时长/番茄二选一”：写入非空时长时清空预计番茄，反之亦然；单纯清空当前字段不清另一个；“清空”按钮两个都清；无变化不写。历史同时存在时定优先级（建议时长优先）并提供清理。
- 测试：单位切换提示、预设编辑、二选一写入。

## 5. 测试计划

1. **解析矩阵**：`0`、`1`、`30`、`45`、`59`、`60`、`90`、`120`、`150`、`2.5`、`2.33`、`30h`、`1d`、`90分钟`、`1.5小时`、`2h30m`、`2h 30m`、空值、非法值。
2. **往返**：分钟 → 存储数字（小时 2 位小数 / 分钟整数）→ 解析 → 分钟；0–99 小时穷举。
3. **运行时一致性**：同一组 fixture 在主界面、kernel、首页、日历得到相同分钟数。
4. **控件**：输入、预设、键盘、移动端、空值、越界、未改动不重写。
5. **显示**：4 种格式 × 典型值 × 各视图。
6. **回归**：现有 `duration-defaults-contract`、`summary-runtime-contract`、`kernel-contract`、`checklist-style-integration-browser`、`settings-v2-browser` 等。

## 6. 风险与取舍

| 风险 | 影响 | 应对 |
|---|---|---|
| 四套解析继续漂移 | 同一任务在不同视图时长不同 | P0 前置；共享 fixture；全局 API |
| 只换控件不修解析 | 日历把 `2.5` 当 15 分钟，kernel 当 2.5 分钟 | P0 必须与 P1 同批 |
| `durationFormat` 切单位改变旧值含义 | 历史数据被重新解释 | 明确单位语义 + 切换确认；接受重新解释，不做换算 |
| 显示格式影响面大 | 列表/导出/测试文案变化 | 默认 `unit`；分阶段铺开 |
| 预设编辑器无单位 | 用户配置出 30 小时预设 | 编辑器显示单位和预览 |
| quickbar 独立打包 | 共用代码难 | 全局 API + fallback + 契约测试 |
| 小时小数精度 | `0.34 → 20m → 0.33` | 2 位小数 + 未改动不重写 |
| 实际耗时与预估两套格式 | 同一弹层出现两种写法 | P3 统一到 `format`，属性模式只管读取 |
